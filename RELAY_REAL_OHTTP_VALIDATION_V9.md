# Relay Real-OHTTP Validation — V9

Status: **PASS (LOCAL LOOPBACK INTEGRATION)**

The frozen V8 `FreshRequestRelay` was exercised with actual encapsulated OHTTP
request and response bytes generated by the V9 RFC adapter. Across two rounds:

- request and response bodies were byte-identical before and after Relay;
- request length was exactly 1079 bytes and response length exactly 800 bytes;
- OHTTP content types and fixed `Content-Length` were enforced;
- one Relay-to-Gateway keep-alive connection was reused;
- inbound `Cookie`, `Authorization`, `X-Agent-ID`, and client `User-Agent` did
  not reach the Gateway;
- the Relay neither parsed the BHTTP plaintext nor possessed Gateway keys.

This is local HTTP/loopback validation, not packet-level or Internet traffic
privacy evidence.
